# Design

Living document. Each design section has an ID, the requirements it satisfies, and the code that implements it.
`scripts/docscheck.mjs` verifies that the requirement IDs exist and the code paths exist. Decisions with trade-offs get an ADR in
`docs/adr/`. The wire protocol and user-visible behaviour are specified in `docs/SPEC.md`.

## DES-001 — Layered core, standard library only

- Satisfies: REQ-DISC-001; REQ-AGENT-001
- Code: core/app; core/agent; core/skills; core/agents; core/prompts
- Notes: `core/app` wires config, discovery, extensions, hooks, provider and agent. Frontends call `app.HandleInput` and render events. The Go core has no third-party dependencies, which keeps the supply chain small and the audit trivial (ADR 0004).

## DES-002 — Events and decisions

- Satisfies: REQ-EXT-001; REQ-HOOK-001
- Code: core/events; core/hooks
- Notes: Every interception point emits an event. Handlers return a `Decision` (block, rewrite arguments, replace output, append to the system prompt). `Multi` merges decisions from hooks and extensions; the first block wins.

## DES-003 — Extension host and wire protocol

- Satisfies: REQ-EXT-001
- Code: core/ext/host.go
- Notes: One child process per extension, speaking JSON-RPC 2.0 over stdio. Host-to-extension calls need a reply; extension-to-host registrations are notifications. Errors and crashes are contained to the extension.

## DES-004 — JS sidecar for Pi and opencode

- Satisfies: REQ-EXT-002; REQ-EXT-003; REQ-EXT-004
- Code: core/ext/sidecar.go; core/ext/sidecar/runner.mjs; core/ext/sidecar/shims
- Notes: Pi and opencode plugins are JavaScript, so a Node or Bun process hosts them. Imports of `@earendil-works/*`, `@opencode-ai/*`, zod and typebox resolve to shims. Unsupported properties and methods return stand-ins and are reported (ADR 0001).

## DES-005 — Trust boundary

- Satisfies: REQ-TRUST-001; REQ-TRUST-002; REQ-SKILL-001
- Code: core/trust; core/app/discover.go; core/app/config.go; core/skills
- Notes: Config is loaded in two scopes, user and project. Only user scope may declare code or credential routing unless the folder is trusted. Trust is recorded per directory, inherited by descendants, and stored with owner-only permissions (ADR 0002).

## DES-006 — Compatibility manifest and drift pipeline

- Satisfies: REQ-PI-001; REQ-PI-002; REQ-PI-003; REQ-EXT-004
- Code: compat/compat.go; compat/pi.json; scripts/upstream-check.mjs; core/ext/jstest/conformance.test.mjs
- Notes: The manifest is the single source of truth for what Pi surface exists and how far Koine goes. The sidecar's behaviour for unsupported properties is generated from it. A conformance test executes the manifest against the real runner (ADR 0003).

## DES-007 — Provider router

- Satisfies: REQ-LLM-001; REQ-LLM-002
- Code: core/llm
- Notes: A `Provider` interface with Anthropic, OpenAI-compatible, Responses, Azure and Gemini implementations (DES-061, DES-062). `Router.Resolve` maps a model id to a provider from built-in names, `prefix/model`, and user-declared providers; credentials follow DES-060. Shared HTTP helper owns retry policy (DES-016).

## DES-008 — Frontend contract

- Satisfies: REQ-FE-001; REQ-FE-002
- Code: core/server; core/tui; cmd/koine
- Notes: Frontends receive a stream of events (`text`, `tool_use`, `tool_result`, `notice`, `error`, `done`). The HTTP server allows one run at a time. The line-mode TUI is dependency-free; Bubble Tea and Wails are separate modules.

## DES-009 — Quality, documentation and agent workflow

- Satisfies: REQ-QA-001; REQ-DOC-001; REQ-AGENTDEV-001
- Code: scripts/sizecheck.mjs; scripts/docscheck.mjs; scripts/covergate.sh; .github/workflows/ci.yml; Taskfile.yml; AGENTS.md
- Notes: `task check` is the local mirror of CI. Rules live in `docs/ENGINEERING.md`; agents read `AGENTS.md`, which points to them. Docs are checked, not trusted (ADR 0005).

## DES-010 — Command line: parse, build one prompt, run print mode

- Satisfies: REQ-CLI-001
- Code: cmd/koine/args.go; cmd/koine/print.go; cmd/koine/main.go; core/app/runopts.go
- Notes: `parseArgs` is a small hand-written parser (the standard `flag` package stops at the first positional and has no `--name=value` plus `@file` handling). `run` takes injected `streams` so the whole command line is testable without touching the process's stdio. `buildPrompt` reads stdin only when it is not a terminal. Per-run overrides travel in `app.RunOptions` inside `app.Options`, and are re-applied by `load`, so `/reload` does not drop them. Text mode keeps only the text after the last tool call as the answer, which makes `koine ... | tool` safe to pipe; JSON mode forwards `agent.Event` unchanged.

## DES-011 — Sessions: Pi v3 files, written as the conversation happens

- Satisfies: REQ-SESS-001
- Code: core/session; core/app/session.go; core/agent/agent.go
- Notes: `core/session` reads and writes Pi's tree format: a header line, then entries linked by `parentId`; the active branch is found from the last entry. `agent.Agent.Persist` is called for every message added to the history, so a crash loses at most the call in flight. A user message of tool results is stored as one `toolResult` entry per result (as Pi does) and merged back on load. The file is created on the first entry, so runs that say nothing leave nothing behind. Thinking blocks are stored in Pi's shape and restored (DES-016); unknown entry types and blocks (custom, labels) stay in the file but are not sent to the model; image blocks are stored in Pi's shape and replayed (DES-032). Files go to `~/.koine/sessions`, not Pi's directory, so the two tools never write the same file by accident; `--session PATH` opens a Pi file directly. Sub-agents get no `Persist`, so their messages stay out of the parent's file.

## DES-012 — Compaction: estimate, cut at a safe message, summarise, record

- Satisfies: REQ-CMP-001
- Code: core/compact; core/agent/compact.go; core/agent/agent.go; core/session/messages.go; core/app/session.go
- Notes: Koine does not yet get token counts from providers (LLM-11), so `core/compact` estimates about four characters per token. `CutPoint` walks back from the newest message until it has kept enough tokens, and only cuts where the first kept message is not a tool-result message; the summary is a user message, so a kept assistant message may follow it. `Agent.Run` checks the budget before every turn and, on a provider overflow error, compacts once and retries once per prompt. `Agent.OnCompact` receives the old history index of the first kept message; the app maps it to a `compaction` entry whose `firstKeptEntryId` comes from `Session.messagesWithIDs`, and refuses to write it if the file and the live history have different lengths. Sub-agents run with no `ContextWindow`, so they never auto-compact.

## DES-013 — Settings: Pi's schema, one manifest, a mapper at the edge

- Satisfies: REQ-CFG-001
- Code: compat/settings.json; compat/settings.go; core/app/config.go; core/app/runopts.go; core/app/session.go; scripts/settings-check.mjs
- Notes: The settings files use Pi's key names so Pi users and Pi docs carry over; only the file location (`.koine`) and a few Koine-only keys differ. `compat/settings.json` is the single place that says, key by key, what Koine does with a Pi setting; `compat.SettingsManifest.Check` is the validator and `Config.normalize` is the mapper from Pi spellings to Koine's fields (`defaultProvider`+`defaultModel` → `model`; string entries of `extensions` → `plugin`, object entries → extension specs). Verified keys must name an existing test, as in `compat/pi.json`. `scripts/settings-check.mjs` reads the markdown tables of Pi's `docs/settings.md` from the published package, so upstream additions show up as drift and are recorded by `task upstream:rebase` as `todo`. Untrusted projects still apply only harmless scalars (model, turns, compaction); `sessionDir`, `defaultTools` and everything that can run code need trust. Precedence for the session directory: `--session-dir`, `$KOINE_SESSION_DIR`, the `sessionDir` setting.

## DES-014 — Model catalog and usage accounting

- Satisfies: REQ-LLM-004
- Code: core/llm/models.json; core/llm/usage.go; core/llm/llm.go; core/llm/openai.go; core/agent/usage.go; core/agent/compact.go; core/session/messages.go; core/app/app.go; core/app/session.go
- Notes: `models.json` is embedded and carries a `source` and `checked` date: its prices come from third-party price pages and have not been verified against the vendor, so users can correct them in `~/.koine/model-catalog.json` (a different file from Pi's `models.json`, which has another schema; it is read for providers and models, DES-061, and `model-catalog.json` has the last word on windows and prices). Entries are matched by id, with an optional `provider/` prefix and a dated suffix. Providers fill `Response.Usage` with cached tokens counted apart from input, whatever the vendor's own accounting. `Agent.record` attaches usage and cost to the assistant message, adds to the totals and emits a `usage` event; a model without a price marks the total as a lower bound (`Unpriced`) instead of adding zero. The context size is the provider's count at the last response plus an estimate of later messages, reset on compaction because the old count no longer matches the history. The session file stores usage under the assistant message's `usage` key using Pi's field names; the exact Pi shape is the best known and is not yet checked against upstream.

## DES-015 — Agent directory and prompt files

- Satisfies: REQ-CFG-002
- Code: core/agentdir/agentdir.go; core/app/sysprompt.go; core/app/runopts.go; core/app/config.go; core/app/discover.go; core/app/session.go; core/skills/skills.go; core/agents/agents.go; core/prompts/prompts.go; core/trust/trust.go; core/agent/agent.go
- Notes: `agentdir.Of(home)` is the one place that knows where the user directory is, so every reader of `~/.koine` goes through it and the override cannot be missed by one of them. The name is `KOINE_AGENT_DIR` rather than Pi's variable, as the settings mapper does for key spellings. Pi's own directory (`~/.pi/agent`) is still read as a fallback for the resources Koine already shared with it. `promptFile` searches a trusted project's `.koine/` then `.pi/`, then the user directory, then Pi's, and returns the first non-blank file; it never joins files. It runs before the command-line options so the options win.

## DES-016 — Thinking, prompt caching and retry

- Satisfies: REQ-LLM-005; REQ-LLM-002
- Code: core/llm/thinking.go; core/llm/anthropic.go; core/llm/openai.go; core/llm/retry.go; core/llm/overflow.go; core/llm/models.json; core/llm/usage.go; core/agent/thinking.go; core/agent/agent.go; core/session/messages.go; core/app/llmopts.go; core/app/app.go; core/app/config.go; core/compact/compact.go; cmd/koine/args.go
- Notes: `llm.ThinkingSettings` turns the explicit level (flag, suffix, `/thinking`), the settings and the catalog into one `llm.Thinking` per request: mode (`adaptive`, `budget` or `effort`), level and budget; the agent builds it for each call, so a `/model` switch picks up the new model's level. `nil` means send nothing, which is the case for models the catalog says do not think and for unknown models nobody asked about; this keeps `defaultThinkingLevel: medium` from sending `reasoning_effort` to a local model that rejects it. The catalog's `reasoning` is `true` or `{mode, max, off}`: `max` is the highest level the model accepts, `off` says what `thinking.type` to send for `off` (Claude Opus 5.5 cannot disable thinking, so it sends nothing). The three Claude entries use Anthropic's adaptive thinking with `output_config.effort`, as its effort page describes; `minimal` is sent as `low`. Budget mode (for catalog entries and unknown `claude-*` models) sends `budget_tokens` and raises `max_tokens` so the budget fits. With thinking on and no limit set, the agent asks for the model's output limit up to 32000, because thinking tokens count against it. A thinking block is an `llm.Block` with `Signature`; a redacted block keeps its payload in `Signature`, as Pi does in `thinkingSignature`. Blocks without a signature (from OpenAI-compatible `reasoning_content`) are shown and saved but never sent back. The Anthropic provider drops all thinking blocks when it has sent `thinking: disabled`. Prompt caching puts `cache_control: ephemeral` on the system prompt (sent as a block), the last tool and the last block of the last user message, three of the four breakpoints the API allows. `retry.go` owns the retry loop: `RetryPolicy` (attempts, exponential backoff with a cap, `Retry-After` up to a limit, a per-attempt timeout) is set on the `Router` from the settings and handed to each provider; non-success answers are `*HTTPError`, so `IsQuotaError` and `IsOverflow` can read the provider and body; a context hook reports each retry to the agent, which emits a notice. `retry.provider.maxRetries` has no counterpart because there is one loop. There is no jitter. Unverified: the wire format is tested against fake servers only, and Pi's built-in thinking budgets and overflow patterns were not compared with ours.

## DES-020 — Session tree: leaf moves, labels, copies and exports

- Satisfies: REQ-SESS-002
- Code: core/session/tree.go; core/session/migrate.go; core/session/export.go; core/session/session.go; core/session/messages.go; core/app/tree.go; core/app/session.go; core/app/config.go; core/tui/tui.go; cmd/koine/main.go
- Notes: A session is a tree of entries and a leaf; moving the leaf (`/tree`) writes nothing, as in Pi, and the next appended entry hangs off the new leaf, so a reopened file starts at its last entry again. Moving to a user message sets the leaf to its parent and hands the text back (there is no editor in line mode, so it is printed). A branch summary is a `branch_summary` entry whose parent is the new position and whose `fromId` is the old leaf; it reaches the model as a user message (`entryMessage`, the only change in `messages.go`). The summariser is `compact.Summarize` over the entries between the old leaf and the common ancestor, newest first within `window - branchSummary.reserveTokens`. Line mode cannot ask a question inside `HandleInput`, so the summary question is `App.Choose`, set by frontends that can ask (the line TUI sets it); without it `--summary` decides, and `skipPrompt` removes the hint. Every `Entry` keeps the line it was read from, so `/clone`, `/fork` and `Fork` copy lines unchanged (ids included, as Pi does); only an entry whose parent was a skipped `session_info` is re-encoded. Appends never touch earlier bytes, and add the newline a hand-edited file may lack. Files older than v3 are migrated in `Open` (ids and parents added, `firstKeptEntryIndex` turned into `firstKeptEntryId`, `hookMessage` renamed `custom`) and replaced atomically after the original is saved as `<file>.v<N>.bak`; `List` migrates in memory only. HTML export is one file with inline style and no scripts; all session text is escaped and only png, jpeg, gif and webp base64 images are embedded.

## DES-030 — Command-line selection of tools, resources, models and extension flags

- Satisfies: REQ-CLI-002; REQ-CLI-004
- Code: cmd/koine/args_resources.go; cmd/koine/args.go; cmd/koine/main.go; core/app/loadopts.go; core/app/toolsel.go; core/app/modelsel.go; core/app/env.go; core/app/discover.go; core/skills/skills.go; core/prompts/prompts.go; core/tools/tools.go; core/tools/builtin.go; core/ext/host.go; core/ext/sidecar/runner.mjs
- Notes: The new options travel in `app.LoadOptions` (inside `app.Options`, separate from `RunOptions`) and are re-applied by `load`, so `/reload` keeps them. `selectTools` is the one place that turns `-nt`, `-t`, `-nbt`, `-xt` and `defaultTools` into the tools offered: `-nt` wins, then plain `-t` names, otherwise the `defaultTools` selection (or everything) minus the built-ins for `-nbt`, adjusted by `+`/`-` entries; `-xt` is applied last. With no tool option and no setting the registry is left as it is, so late-registered tools stay visible. Explicit `-e`, `--skill` and `--prompt-template` paths come before discovered ones and win name clashes; `-e` runs code, so `extensionTargets` skips it in an untrusted folder, counts it with the other skipped project code and adds a warning that names the paths; print, JSON and server runs print startup warnings on stderr (`warnAll`). `--skill` and `--prompt-template` are data and load in any folder (ADR 0002 guards code; skills keep the hidden-text audit). Model matching lives in `core/app` rather than `core/llm`: candidates are the catalog entries; an exact id is kept, otherwise ids and names are compared with case and punctuation ignored, a provider with a key beats one without, and an undated id beats a dated one. The `--api-key` value is the credential of the provider of the first model only and sits above `auth.json` (`Router.RuntimeKeys`, DES-060). Extension options need the extensions to be loaded before the command line can be read: the first parse keeps unknown long options, the app starts, and a second parse with the registered types (`register_flag`) reads string values and rejects unknown names; values are sent to the extensions as a `flags` notification. Process markers are set by `main` through `app.SetProcessMarkers`; the bash tool takes its `KOINE_SESSION_*` variables from `shellEnv`, called for each command.

## DES-031 — JSON event stream

- Satisfies: REQ-CLI-003
- Code: cmd/koine/jsonmode.go; cmd/koine/print.go; core/agent/pievents.go; core/agent/compact.go; core/agent/agent.go; core/app/pievents.go; core/app/session.go; core/app/tree.go; core/app/llmopts.go; core/session/custom.go; core/session/session.go; core/tools/updates.go; core/llm/retry.go; core/ext/host.go; core/ext/sidecar/runner.mjs
- Notes: `--mode json` is a translator from what the agent and the app already report to Pi's records (https://pi.dev/docs/latest/json). `App.OnMessage` is called from the same place that saves messages, so the stream sees every message in order: the assistant message (with usage, cost, `api` and `thinkingLevel`) yields `message_start`, one start/delta/end triple per content block, and `message_end`; the tool-result message yields the `toolResult` messages and `turn_end`, which waits until the session entries of those results were reported. Pi's state events are `agent.Event` values with Pi's type names and their fields, under Pi's names, in `Event.Data` (`core/agent/pievents.go`), so the stream writes them as they are and the server and TUIs get them without a second translation. Sources: `Agent.complete` reports provider retries (`auto_retry_start`/`_end`, from the existing retry notice, no change to the retry loop); `Agent.CompactFor` reports compaction with its reason and, through `Summarizing`, the retries of the summarisation call (a one-function `llm.WithRetryResume` tells when a retry starts); the app reports `session_info_changed` and `thinking_level_changed` after writing their session entries, and `entry_appended` for every entry through `Session.OnAppend` (re-attached whenever the session is replaced, `setSession`); `HandleInput` hands its emit to the app (`App.event`) so entries written outside the agent loop, by a command or an extension, are reported too. `firstKeptEntryId` is read from the compaction entry just written (`Agent.KeptEntryID`). `Agent.Steer` and `Agent.FollowUp` fill the queues that `pi.sendUserMessage(text, {deliverAs})` addresses; steering text rides in the next tool-result message and a follow-up starts another turn when the agent would stop; `queue_update` is emitted from the agent loop only, when the queues differ from the last report, so emit is never called from two goroutines. `tools.WithUpdates` lets a running tool report partial output (`tool_execution_update`); the JS sidecar's `onUpdate` sends `tool_update` notifications keyed by tool and call id. `pi.appendEntry` becomes a `custom` session entry (`Session.AppendCustom`). A failed provider call becomes an assistant message with `stopReason: "error"`. Notices and errors go to stderr, so stdout holds only the stream.

## DES-032 — Images: one block type, converted at the edges

- Satisfies: REQ-LLM-006; REQ-CLI-005
- Code: core/imgutil/imgutil.go; core/llm/image.go; core/llm/llm.go; core/llm/anthropic.go; core/llm/openai.go; core/llm/usage.go; core/llm/models.json; core/tools/readimage.go; core/tools/builtin.go; core/agent/images.go; core/agent/agent.go; core/compact/compact.go; core/session/messages.go; core/app/fileargs.go; core/app/imageopts.go; core/app/app.go; cmd/koine/print.go; cmd/koine/jsonmode.go
- Notes: `llm.Block` has one image shape, `Type: "image"` with `Source` (`base64`, `media_type`, `data`), which is Anthropic's wire shape, so that provider marshals it as it is. A `tool_result` block carries its images in `Images` (not serialised); `Block.MarshalJSON` turns them into the content array the Messages API wants, and `toOpenAI` emits them as a user message after the tool messages. `core/imgutil` is the only place that looks inside image bytes: `Sniff` decides the type from the first bytes (file names play no part), `Prepare` applies the 2000 by 2000 and 4.5 MB limits with a box filter and `image/png`, `image/jpeg` and `image/gif`, and `ReadFile` reads only a header to decide whether a file is an image at all, so the `read` tool pays nothing for text. Tools attach images through the context (`tools.WithImages`, `AttachImage`, `ResizeImages`), the same pattern as partial results; the agent puts a sink in every tool context and moves the collected images into the result block, so `read.go` changes by one hook (`readImage`) and a rewrite of the tool keeps working. `Agent.RunWithImages` stores images for the next `Run` instead of changing its signature. Gating is `Agent.forModel`, called where the request is built: it returns a stripped copy of the history (`llm.StripImages`) when `images.blockImages` is set or the catalog says the model has no `image` input, and announces each reason once. The history is never modified, which is what lets a model switch bring images back. Sessions: `piBlock` gained `data` and `mimeType`; `contentBlocks` reads user and toolResult content in order, and the older text-joining path stays for content without images. `App.FileArgs` and `App.PipedInput` produce `Attachments` (text, image blocks, notes) for the command line; `HandleInputImages` is `HandleInput` plus images. Open points: Pi's default byte cap and `inputLimits.images` are not documented on the pages read, so 4.5 MB is Koine's choice (under Anthropic's 5 MB); WebP and BMP are never resized; `custom_message` entries with images and the extension `input` event's images (EXT-15) are not handled; the HTTP server takes text only.

## DES-040 — Built-in tools: Pi's behaviour in the standard library

- Satisfies: REQ-TOOL-002; REQ-TOOL-003; REQ-TOOL-004; REQ-TOOL-005
- Code: core/tools/builtin.go; core/tools/tool_files.go; core/tools/editdiff.go; core/tools/diff.go; core/tools/mutq.go; core/tools/paths.go; core/tools/truncate.go; core/tools/tool_search.go; core/tools/tool_grep.go; core/tools/gitignore.go; core/tools/tool_bash.go; core/tools/shell.go; core/tools/shell_unix.go; core/tools/tools.go; core/agent/prompt.go; core/agent/usercontext.go; core/app/toolsel.go; core/app/userbash.go; core/ext/host.go; core/ext/sidecar/runner.mjs
- Notes: `tools.Options` (working directory, home, `shellPath`, `shellCommandPrefix`, per-call environment, ripgrep choice) is the one way the app configures the seven built-ins. Truncation is shared (`TruncateHead` for read, grep, find and ls; `TruncateTail` for bash) so every tool says the same thing: what was cut, and how to get the rest. `edit` matches all `edits[]` against the original, in the fuzzy-normalised text if any `oldText` is not found verbatim (as Pi does), and holds the file's mutation-queue lock for the whole read-modify-write; the lock key is the real path, so symlink aliases queue together. The diff is a small LCS line diff with the common prefix and suffix cut off, falling back to one replaced block when the changed region is huge. `Shell.Run` starts the shell in its own process group and kills the group on timeout or abort; output goes to an accumulator that keeps the newest 200KB in memory and everything in a temp file once it outgrows that. Partial output goes to the callback installed with `tools.WithUpdates`, which the agent already forwards. `grep` only asks ripgrep (or the Go search) _where_ the matches are and prints them itself, so context lines, line caps and the output format are the same on both paths; the Go search and `find` walk the tree with a small `.gitignore` matcher (`gitignore.go`) because `tools` may use only the standard library (ADR 0004). `grep`, `find` and `ls` are hidden in the registry rather than removed (`Registry.Hide`), so extensions that arrive later still show and sub-agents can still be given them. The system prompt is built in `core/agent/prompt.go` from the active tools' `PromptSnippet` and `PromptGuidelines` (the `tools.Prompted` interface); `!cmd` output enters the conversation through `Agent.AddUserContext` and never through the model's tool path, so tool hooks do not see it. Print and server runs set `App.NoUserBash` so piped or networked text cannot become a shell command.

## DES-021 — Streaming providers and the agent loop

- Satisfies: REQ-LLM-003; REQ-AGT-001
- Code: core/llm/stream.go; core/llm/stream_anthropic.go; core/llm/stream_openai.go; core/llm/retry.go; core/agent/loop.go; core/agent/toolexec.go; core/agent/queue.go; core/events/events.go; core/session/messages.go; core/server/server.go; core/app/llmopts.go; core/app/app.go; core/ext/sidecar/runner.mjs
- Notes: `llm.Streamer` is optional: `llm.Stream(ctx, p, req, fn)` uses it when the provider has it and calls `Complete` otherwise, so `Missing`, test fakes and other providers keep working. `retryLoop` is the retry code of DES-016 with the request abstracted out, so `postJSON` and `openStream` share it; a stream is retried until the answer is a 200 and never after. `respStream` wraps the body: every read that returns data restarts an idle timer, and the timer cancels the request with a cause that turns the read error into "no data from the provider for N (httpIdleTimeoutMs)". The client's overall timeout is dropped for streams. The Anthropic and OpenAI readers build the same `Response` that `Complete` returns (and share its parsers for a server that answers with JSON), report increments through `StreamEvent`, and on failure return the text and thinking received so far, which is what an aborted turn keeps. `Agent.Run` splits into `Run` (input hook, queue pickup, turn limit), `turn` (one request plus its tools), `execTools` (check in order, run together, answer in order) and `abortTurn`. Events from tools on other goroutines and from `Steer` calls reach the caller's `emit` one at a time through a mutex in `Run`. The `queue` holds steering and follow-up text under its own lock; `take` hands out one message or all, as the mode says. An aborted turn adds an assistant message with `StopReason "aborted"`; `requestMessages` leaves such messages out and gives every unanswered `tool_use` a synthetic error result, so the same function also repairs sessions cut short by a crash. The `context` event, `TransformContext` and `PrepareNextTurn` all work on the request copy, never on `History`. A `Decision` gained `isError`, `terminate` and `messages`; the sidecar maps Pi's `tool_call` `terminate` and `tool_result` `isError` and never subscribes to `context`, because its payload is Koine's message shape. Deliberately not done: Pi's `message_*` and `tool_execution_*` extension events, streaming partial tool-call JSON parsing, a mutation queue (TOOL-11), and rendering of deltas in the frontends.

## DES-041 — Terminal UI: a pure model, a screen painter and a thin terminal shim

- Satisfies: REQ-TUI-001
- Code: core/tui/ui.go; core/tui/ui_keys.go; core/tui/ui_cmds.go; core/tui/run.go; core/tui/term_unix.go; core/tui/keys.go; core/tui/keybindings.go; core/tui/editor.go; core/tui/editor_view.go; core/tui/complete.go; core/tui/markdown.go; core/tui/toolview.go; core/tui/transcript.go; core/tui/footer.go; core/tui/screen.go; core/tui/selector.go; core/tui/tree_view.go; core/tui/theme.go; core/tui/themeload.go; core/tui/settings.go; core/tui/extedit.go; core/app/tuiopts.go; core/app/tree.go
- Notes: `UI` is a pure model: `Key`, `Event` (agent events), `Tick` and `Resize` go in, `Frame()` returns the live area and `Take()` returns actions for the loop (run, interrupt, external editor, suspend, copy, quit). `Loop` owns the goroutines: an input reader, `HandleInput` run in its own goroutine, and a message channel that also carries `App.Choose` questions and `App.PrefillEditor` text back to the model. The `Terminal` interface (`Size`, `Input`, `Output`, `ResizeCh`, `Raw`, `Suspend`, `Exec`) is the only contact with a terminal; `term_unix.go` implements it with ioctls (raw mode with VMIN 0 and VTIME 1 so the reader can pause for a child program) and is exercised by one pty test; other systems fall back to the line loop. Regular mode prints each finished block once and erases and redraws only the live area (`Screen.Draw`); a resize, Ctrl+O, Ctrl+T or theme change clears the screen and scrollback and reprints all blocks. Blocks that are still running stay in the live area. Keys are decoded from CSI, SS3, the kitty protocol (`CSI u`) and modifyOtherKeys, with bracketed paste; a lone Escape is resolved after about 40 ms. Key ids and defaults are Pi's; `keybindings.json` replaces the defaults for an id, and an empty list disables it. Themes are Koine's reading of Pi's theme page (the token list is not published): JSON with `vars` and `colors`, missing tokens filled from the built-in theme of the same appearance, 256-colour reduction when true colour is off. Markdown, tables and the small lexer-based highlighter, the tool-call views (edit diffs are built from the call's arguments with a line-based LCS) and the footer are functions from data and width to lines. The tree navigator is a `TreeNav` over `Session.Rows`; choosing an entry runs `/tree <id>` (or `/fork <id>`) through the app, which hands a returned user message to `App.PrefillEditor`. Settings are `app.TUISettings` inside `Config`: project values are ignored in an untrusted folder because `externalEditor` names a program (ADR 0002), and `tui.SaveSetting` writes only a plain-JSON user `settings.json`. Streaming events (`text_delta`, `thinking_delta`) grow an unfinished block in the live area, `user_message` shows a queued steering or follow-up message, `aborted` finishes the open blocks, and `tool_delta` and `queue_update` are not drawn. Unverified against Pi: the double Ctrl+C rule, collapsed line counts, `@` ranking and hyperlink detection; rendering is tested as pure functions only.

## DES-050 — MCP client in the standard library

- Satisfies: REQ-MCP-001; REQ-MCP-002; REQ-MCP-003
- Code: core/mcp/protocol.go; core/mcp/client.go; core/mcp/stdio.go; core/mcp/proc_unix.go; core/mcp/proc_windows.go; core/mcp/http.go; core/mcp/config.go; core/mcp/configwrite.go; core/mcp/secrets.go; core/mcp/manager.go; core/mcp/registry.go; core/mcp/tool.go; core/mcp/resources.go; core/mcp/output.go; core/mcp/log.go; core/mcp/oauth.go; core/mcp/oauthstore.go; core/mcp/mcptest/mcptest.go; core/app/mcpwire.go; cmd/koine/mcp_cmd.go
- Notes: `core/mcp` is JSON-RPC 2.0 written on the standard library (ADR 0004). A `Transport` (`Start`, `Do`, `Send`, `Alive`, `Close`) hides stdio (newline-delimited JSON on a child process in its own process group) and streamable HTTP (one POST per message, answered with JSON or an SSE stream, `Mcp-Session-Id` and `MCP-Protocol-Version` headers, `DELETE` on close); the legacy two-endpoint SSE transport is refused. `Client` does the handshake, paging, and per-request timeouts that restart on progress notifications (every request carries a progress token), answers the server's `ping` and refuses its other requests. `Manager` owns the servers of a session: it resolves `${ENV}` and `!command` values at connect time, registers each tool in `core/tools` under `mcp__<server>__<tool>` (invalid characters become `_`, collisions and names over 64 characters get a hash suffix) as a `tools.Prompted` tool, and applies the exposure: `direct` tools are registered, `deferred` ones are registered and hidden (`Registry.Hide`) until the `tool_search` tool, which exists while any tool is deferred, shows them, `hidden` ones are not registered. A dropped connection keeps its tools registered and reconnects on the next call, after which an expired HTTP session is renewed once. Results are rendered by `Render` (text, images through `tools.AttachImage`, binary resources saved to private temporary files, a 20 KB middle cut with the whole text saved). Trust (ADR 0002) is decided in one place: `mcp.Load(cwd, home, trusted)` does not interpret project files unless trusted, only counts their servers; the app and the CLI both go through it, and `/trust` reloads. OAuth (`oauth.go`) is `Authorizer` for the HTTP transport: stored token, refresh, and on a failed refresh `AuthRequiredError`; `Login` runs discovery, registration, PKCE and the loopback callback and takes the browser opener as a parameter so the whole flow runs against a fake server in tests. Tokens live in `mcp-auth.json` written atomically with mode 0600. `core/mcp/mcptest` is a fake server (stdio through the test binary re-executing itself, and HTTP) shared by the tests. `core/app/mcpwire.go` is the only app wiring: `startMCP` after the tool registry is built, `closeMCP`, and `/mcp`. Alternatives rejected: a third-party MCP SDK (ADR 0004); running MCP servers inside the JS sidecar (no benefit, a second process layer); a codemode sandbox (LLM-48 stays open, so `codemode` exposure is treated as `deferred` and the default is `direct`, see compat/DIVERGENCES.md).

## DES-060 — Credentials: a store, a resolver and one precedence list

- Satisfies: REQ-AUTH-001; REQ-AUTH-002
- Code: core/auth/store.go; core/auth/secret.go; core/auth/prompt.go; core/llm/router.go; core/app/providers.go; core/app/authcmd.go; core/app/app.go; cmd/koine/auth.go
- Notes: `core/auth` knows nothing about providers or projects, which is what keeps the trust rule simple: it only ever sees user-level values. `Store` reads `auth.json` as raw JSON per provider, so an entry it does not model (Pi's OAuth login) survives a rewrite; it writes through a temporary file created 0600 in a 0700 directory and renames it, refuses to touch a file that is not valid JSON, and holds one in-process mutex (there is no cross-process lock, so two Koine processes logging in at the same moment can lose one write). `Resolver.Resolve(value, cache)` implements `!command`, `$VAR`/`${VAR}`/`$$`/`$!`; the command runs with `sh -c` (`cmd /C` on Windows) under a 10 second limit, and only its trimmed standard output counts. `cache` keeps the result, an error included, for the life of the process (auth.json, as Pi describes); without it the result is reused for `Burst` (5 seconds) only, because `hasCredentials` resolves every candidate model during `--model` matching and a password manager must not be asked a dozen times. Pi says models.json commands are not cached; this is the one deliberate difference. The `llm.Router` holds the precedence list in one function, `credential`: `RuntimeKeys` (set by `App.applyRuntimeKey` for the provider of the first model; it replaces the earlier trick of overriding one environment variable, which sat below auth.json), `Stored` (a callback into the store, with the key already resolved), the provider's `apiKey` from models.json (through `Router.Secret`), then the provider's variables, read first from the entry's `env` object. A failure at a higher level is remembered and returned only if every lower level also finds nothing, as an `invalid` error rather than `missing`; `koine auth check` turns the two into exit codes 2 and 1. A provider without a credential still resolves to `llm.Missing` with the reason, so frontends start. `ProviderSetup` (`core/app/providers.go`) builds the router, store and resolver from the settings, the agent directory's `models.json` and, when the folder is trusted, the project's; `koine auth` and `App.load` both use it, so `check` answers what a session in the same directory would find. The resolver lives on the `App`, so a reload keeps the cached commands. `/login` and `/logout` are `App.authCommand`: the key comes from `App.Prompt` or, by default, `auth.ReadSecret` on the terminal (stty -echo, restored by a defer; the standard library has no portable way, and Windows falls back to a visible read with a notice); `NoUserBash` runs refuse. The full-screen UI should set `App.Prompt` so that the question goes through its own editor. Not done: OAuth, cloud credential chains, and Pi's `ANTHROPIC_OAUTH_TOKEN`.

## DES-061 — Providers: built-in table, models.json overlay, per-model settings

- Satisfies: REQ-LLM-007; REQ-LLM-008
- Code: core/llm/providers.go; core/llm/router.go; core/llm/modelsfile.go; core/llm/compat.go; core/llm/openai.go; core/llm/anthropic.go; core/llm/usage.go; core/app/providers.go; core/app/app.go; core/app/modelsel.go
- Notes: `providerTable` is the one list of built-in providers: id, display name, protocol (`api`), endpoint, key variables, whether it is local. `Router.lookup` overlays the `ProviderConfig` of the same name on the table entry (a custom provider has no entry underneath, and then needs `baseUrl`), and a matching `models[]` entry overlays that again for `api`, `baseUrl`, `headers`, `compat` and `samplingParams`; `Router.build` turns the result into one of the five protocols (`anthropic-messages`, `openai-completions`, `openai-responses`, `azure-openai-responses`, `google-generative-ai`) and reports any other `api` as a provider that fails with that message. Koine's older provider shape (`type`, `apiKeyEnv`, in the `providers` setting) maps onto the same struct and is replaced, whole, by a provider of the same name in models.json. A provider that is custom and names no key source may need none (a local gateway); a built-in with only a `baseUrl` still needs its key. `ReadModelsFile` returns warnings for what it does not act on (unknown provider, model and `compat` keys, an unsupported `api`, a provider nothing can reach) and never fails because of them; only invalid JSON is an error, reported as a startup warning. `Catalog.AddProviders` turns declared models and `modelOverrides` into catalog entries (Pi's defaults: 128000 window, 16384 output, text input; no `cost` means unknown cost, never zero), so thinking, compaction, image gating, `--list-models` and `--model` matching work for them without a second table; the order is built-in catalog, models.json, `model-catalog.json`, and the catalog is rebuilt on every load. The OpenAI-compatible provider applies six compat flags (`OpenAIFlags`); the rest are listed by `UnusedCompat`. Default OpenAI stays on Chat Completions: `api: "openai-responses"` is opt-in, because Chat Completions is what OpenAI-compatible proxies (`OPENAI_BASE_URL`) speak. A project `models.json` is read only when the folder is trusted (`NewProviderSetup`), for the reason ADR 0002 gives for the `providers` setting: it chooses where keys are sent and can carry commands. Endpoints in the table were not compared with Pi's registry.

## DES-062 — Responses, Azure and Gemini providers; error bodies

- Satisfies: REQ-LLM-009; REQ-LLM-010; REQ-LLM-011
- Code: core/llm/responses.go; core/llm/stream_responses.go; core/llm/gemini.go; core/llm/errors.go; core/llm/retry.go; core/llm/stream.go
- Notes: Each new provider implements `Complete` and the optional `Streamer`, uses `postJSON`/`openStream` (so retry, idle timeout, `Retry-After` and quota detection are shared), and falls back to parsing a plain JSON body when a streaming request is not answered with an event stream. `Responses` converts messages to input items (assistant text as an easy message, calls as `function_call` with only `call_id` so that no reasoning item is required when `store` is false, results as `function_call_output`, images of a tool result as a following user message as for Chat Completions) and sends tools with `strict: false` because the API defaults to strict schemas, which Koine's tool schemas are not. Streaming forwards deltas and takes the final `Response` from the `response.completed` or `.incomplete` event, which carries every item and the usage, so nothing is assembled twice; a stream that ends without it returns the text received and an error. Azure is `Responses` with `KeyHeader: "api-key"`, a `Query` of `api-version=…` and a deployment map applied to the model id; its settings are read through `Router.envFor`, so an auth.json entry's `env` object wins. `Gemini` builds `contents` (role `model` for the assistant, `functionResponse` named after the call found earlier in the history, `inlineData` images, thinking blocks left out), `systemInstruction`, `generationConfig.thinkingConfig` and `functionDeclarations` with `parametersJsonSchema` (full JSON Schema, so no schema rewriting). Gemini calls carry no id unless the API gives one, so a random `call_…` id is made; `geminiAcc` folds streamed chunks and is also used for a non-streamed body, including the JSON array a server returns when it ignores `alt=sse`. Thought signatures are not stored, because `llm.Block` has no field for them on tool calls and sessions would need one; models that require them may reject long tool conversations. `ErrorMessage` extracts the message from the common JSON error shapes and `HTTPError.Error` prints it with a hint for 401, 402 and 403 (`Hint`), which names the provider's variables from the table; the raw body stays in `HTTPError.Body` for overflow and quota matching. All wire formats were written from the vendors' documentation and tested against fake servers only.
