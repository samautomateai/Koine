# Gap assessment: Extensions behaviour and packages

Upstream: Pi 1.5.2 (TypeScript). Re-audited on 2026-11-12 against Koine at `origin/main` 1059650 (after #34), reading the code and tests and, for Pi, the 1.5.2 source tree (`packages/coding-agent`: `docs/extensions.md`, `docs/packages.md`, `src/core/extensions/loader.ts`, `src/core/package-manager.ts`) and running the upstream example extensions. See [the summary](../gap-assessment.md).

## Extension system and packaging: parity gap assessment (Pi 1.5.2 vs Koine)

`go run ./cmd/koine -compat` reports 81 verified, 17 inert, 84 unsupported and 15 todo of the 197 extension API items in `compat/pi.json` (51/30/97/19 at the first assessment). Rows below cite the manifest where they overlap it. Where this file and the manifest disagree, the code and tests decide; the disagreements are listed under the table.

Upstream paths are relative to `packages/coding-agent/`. In evidence cells `app.`, `ext.`, `pkgs.`, `agent.`, `events.` and `tools.` are Go packages under `core/`, `koine.` is `cmd/koine`, and `js` names a test in `core/ext/jstest/`.

### Upstream examples vs Koine sidecar

## Top 5 gaps

1. Shim export surface (EXT-07, EXT-06): 28 of the 78 upstream examples do not load, 26 of them on a missing named export.
2. Session-bound extension API (EXT-48, EXT-49, EXT-57): `ctx.sessionManager` is empty, commands cannot start a new session, fork or navigate, and `ctx.compact`/`abort`/`getContextUsage` are inert, so state-rebuilding and handoff-style extensions do not work.
3. Tools and events (EXT-17, EXT-18, EXT-53): `setActiveTools` and the active set, tool definition fields such as `executionMode` and `prepareArguments`, and the agent and message events (`agent_settled`, `message_*`) are open.
4. Providers and models from extensions (EXT-31, EXT-50, EXT-56): `registerProvider`, model and thinking access and the provider request hooks are inert or missing.
5. Closed since the first assessment: Pi packages (EXT-34 to EXT-41; REQ-PKG-001..003), dialogs, `ctx.mode` and `hasUI` (EXT-24 to EXT-26), tool and event fidelity (EXT-12 to EXT-15, EXT-20, EXT-45), extension flags (EXT-30), the event bus and `sendMessage` into context.

## Questionable upstream features we should NOT copy

- **jiti plus bundled virtual modules as the only module story.** Koine's native Bun/Node loader is simpler. Match the export surface (EXT-07), not the loader.
- **In-process extension execution with shared classes.** One crashing or hanging extension can take down the host. Koine's per-extension sidecar processes are safer, so keep them.
- **Fail-open vs fail-closed split by event.** Upstream isolates errors for most events but lets `tool_call` throws propagate. This is inconsistent. Define one rule: gates fail closed, observers fail open.
- **Package install running arbitrary npm and git operations at startup.** Pi auto-reinstalls missing project packages on launch and caches `-e` packages. Koine should install only on an explicit command, use pinned hashes, and run with `--ignore-scripts`.
- **pi-tui component API exposed to extensions.** Making `Component`, `Editor`, overlays and `custom()` part of the compatibility contract ties every frontend to terminal rendering. Offer text-level UI methods instead (EXT-28).
