Upstream: Pi 1.5.2 (TypeScript). Compared against Koine at the commit that added this file. Produced by reading both code bases; statuses were verified in Koine's code, not assumed. See [the summary](../gap-assessment.md).

## Extension system and packaging: parity gap assessment (Pi 1.5.2 vs Koine)

I read the code and ran `go run ./cmd/koine -compat` (at the time of the first assessment: 51 verified, 30 inert, 97 unsupported, 19 todo; after the extension API and RPC work: 81 verified, 17 inert, 84 unsupported, 15 todo). I did not execute anything from the upstream tree. Two things are inferred rather than run:

- **Example link check:** it ran as a static script over the example imports and the shim export lists.

## Top 5 gaps

1. Pi package support (EXT-34 to EXT-38, EXT-41; built, see REQ-PKG-001..003, with the caveats in the rows): `install`/`remove`/`update`/`list` over npm, git and local sources, the `pi` manifest, and package roots fed to the skill, prompt and extension loaders. Without this, almost no published Pi package can be used.
2. Shim export surface (EXT-07, EXT-06): a missing named export makes the extension fail to load. About a third of the examples fail on this alone.
3. Interactive UI for extensions (EXT-24, EXT-25, EXT-26): built (REQ-EXT-005, REQ-RPC-001): `mode` and `hasUI` are real, dialogs reach the terminal prompts or the RPC client, and approval-style extensions (`permission-gate`) get their answer.
4. Tool and event fidelity (EXT-12, EXT-13, EXT-14, EXT-20, EXT-45): built (REQ-EXT-006..009): a throwing gate fails closed, `input` patching and `isError` are applied, `AbortSignal` aborts, and arguments are coerced and checked.
5. Session-bound features (EXT-17, EXT-23): lifecycle gates, custom messages and `sendMessage` into context are built (REQ-EXT-007, REQ-EXT-010); message and entry renderers, `message_*` and the provider hooks are open.

## Questionable upstream features we should NOT copy

- **jiti plus bundled virtual modules as the only module story.** Koine's native Bun/Node loader is simpler. Match the export surface (EXT-07), not the loader.
- **In-process extension execution with shared classes.** One crashing or hanging extension can take down the host. Koine's per-extension sidecar processes are safer, so keep them.
- **Fail-open vs fail-closed split by event.** Upstream isolates errors for most events but lets `tool_call` throws propagate. This is inconsistent. Define one rule: gates fail closed, observers fail open.
- **Package install running arbitrary npm and git operations at startup.** Pi auto-reinstalls missing project packages on launch and caches `-e` packages. Koine should install only on an explicit command, use pinned hashes, and run with `--ignore-scripts`.
- **pi-tui component API exposed to extensions.** Making `Component`, `Editor`, overlays and `custom()` part of the compatibility contract ties every frontend to terminal rendering. Offer text-level UI methods instead (EXT-28).
