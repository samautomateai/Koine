Upstream: Pi 1.5.2 (TypeScript). Re-audited on 2026-11-12 against Koine at 1059650 (origin/main after #34): every row was checked against the code and the named tests, and against Pi's published docs (pi.dev/docs/latest: providers, models, models-configuration, cli, mcp). Pi's TypeScript source on GitHub was not reachable during the audit, so behaviour that only the source shows is marked as not compared. Statuses are HAVE, PARTIAL, MISSING or BY DESIGN. Priority is the importance of what is still missing, so a HAVE row keeps its old priority but no longer counts as open. Every provider is tested against fake servers only. See [the summary](../gap-assessment.md).

**Top 5 gaps**

1. Wire compatibility keys (LLM-03, LLM-36, LLM-50, LLM-51). Koine acts on 6 of Pi's roughly 30 Chat Completions `compat` keys and none for Anthropic, and ignores `thinkingLevelMap`, `inputLimits` and `cost.tiers`. Real OpenAI-compatible and Anthropic-compatible gateways are where this shows.
2. Non-Anthropic model metadata and provider breadth (LLM-11, LLM-10, LLM-13, LLM-54). Only Claude models have built-in windows and prices, and about 15 of Pi's providers are not built in.
3. Session fidelity of the model (LLM-35). The session never records `model_change`, so resuming does not restore the model; `defaultProvider` alone is not honoured.
4. Context and cost accuracy (LLM-31, LLM-28, LLM-29). No silent-overflow check, no reasoning-token count, no jitter in retries.
5. Extension-provided models and codemode (LLM-37, LLM-38, LLM-48). Extension providers, virtual models and the codemode sandbox are not built; Pi's default MCP exposure depends on codemode.

**Questionable upstream features we should NOT copy**

- Cache warming (LLM-26) was first skipped as a cost risk; it is now built, global-only, and applies only to models that declare a cache lifetime.
- Classifier and image-generation model types with TypeSafe/Jev, Cloudflare System One and OpenAI Decisions (LLM-39, BY DESIGN): vendor-specific, not coding-agent essentials, and they add a second model abstraction.
- Radius, Xiaomi/Qwen/ZAI token-plan regional provider entries, and Radius OAuth (LLM-10, LLM-20; the other LLM-20 logins are not built): affiliate or region-variant providers that add maintenance. Ship a generic `baseUrl` + env-key mechanism, and let users add them through custom providers.
- Virtual-model routers with session-branch state (LLM-38): a large coupling between sessions, extensions and model dispatch. A simple model-per-subagent setting covers most real use.
- Automatic, default-on codemode activation, and the `codemode` default exposure for MCP tools (LLM-46/48): MCP tools stay invisible to the model until it writes scripts. That is surprising and hard to permission-gate, since nested calls bypass the model's visible tool pipeline. Default MCP tools to `direct`, with deferred search as an opt-in (done: REQ-MCP-001; `codemode` exposure is read as `deferred`).
